# Pseudolife-MCP

[英語版 README(正典)](../../README.md) — 同期バージョン: v10 (2026-09-04)

**Claude Code、Codex、その他の MCP クライアントに永続的な長期メモリを提供します。**

コーディングエージェントに、セッションをまたいで保持される長期メモリを与える MCP サーバーです。コンテキストの圧縮や新しいタスクの開始を経ても記憶は失われません。コーディングエージェントが知性であり、このサーバーはそのディスク上のメモリという位置づけです。

提供する機能:

- **正直に忘れる連想メモリ** — 密ベクトル検索と語彙検索を組み合わせたハイブリッド検索を備えるフラットな類似度ストアに、矛盾検出と置き換え(supersession)を組み合わせています。訂正は古い回答の横に積み上がるのではなく、それを置き換えます。
- **雰囲気ではなく正準的なファクト** — `entity.attribute` スロットごとに *現在の* 値は 1 つだけ(複数の値を同時に保持できるスロットの場合はメンバー集合)。訂正は黙って上書きするのではなく明示的に置き換え、完全なバージョン履歴が保持されます。
- **ドリーム(Dreams)** — ユーザーが離席している間に、抽出器がメモリストリームを正準的なファクトとナレッジグラフへ統合します。
- **自身の作業から得る教訓** — 成功、行き詰まり、そしてユーザーからの訂正が「やるべきこと・避けるべきこと」のガイダンスとなり、毎回のセッション開始時に提示されます。
- **思考の様子を観察できる Web コンソール** — Cortex Console では、メモリストリーム、ファクト履歴、ナレッジグラフのアトラス、セッションのエピソード、ドキュメント RAG を閲覧できます。

## クイックスタート

コマンド 2 つだけです。Docker も、セットアップが必要なデータベースも、コンテナランタイムも不要です:

```bash
pip install "pseudolife-mcp[lite]"
claude mcp add --scope user pseudolife-memory -- pseudolife-mcp
```

Claude Code の代わりに Codex を使う場合も、手順は同じです:

```bash
pip install "pseudolife-mcp[lite]"
codex mcp add pseudolife-memory -- pseudolife-mcp
```

あとは、どちらのコーディングエージェントでも *「ステージングのマシンは haze-02 だと覚えておいて」* と伝えるだけです。数日後の新しいセッションで *「ステージングはどのマシン?」* と尋ねれば、メモリから答えが返ってきます。すべての内容は `http://127.0.0.1:8765/ui/` の Cortex Console で閲覧できます。

最初のセッションでデーモンが自動的に起動し、組み込みの PostgreSQL をプロビジョニングして埋め込みモデルをダウンロードします(これは初回のみの処理です)。Lite にはドリーム**抽出器(extractor)**が同梱されていないため、正準的なファクトは自動では現れません。この構成では、OpenAI 互換エンドポイントを設定するまで `memory_fact_set` だけが唯一の**コーテックス(cortex)**書き込み手段になります。

### 永続ティア — Docker

長期運用するバンクには、上記のすべてに加えて、同梱の抽出器、外部ボリューム、ヘルスチェック付きのサービス群、バックアップ/ロールバックのしくみが必要です。Docker と、MCP 対応のコーディングエージェントが少なくとも 1 つ必要です — Claude Code、Codex、Gemini CLI はエンドツーエンドで接続済みで、それ以外のエージェントにはそのまま貼り付けて使える設定が提供されます。クローンから最初の記憶までコマンド 1 つで到達できます:

```bash
git clone https://github.com/Pseudogiant-xr/Pseudolife-MCP.git
cd Pseudolife-MCP
ops/install.sh          # Linux / macOS
ops\install.ps1         # Windows (pwsh 7+)
# Codex: add --client codex / -Client codex
# Both:  add --client both  / -Client both
# Gemini: add --client gemini — or several: --client claude,codex,gemini
# Other MCP agents (Cursor, Windsurf, Zed, ...): --client generic
```

インストーラーは前提条件をチェックし(不足があれば、そのまま実行できる修正コマンドを 1 行で表示します)、どのドリーム抽出器を使うかを尋ねます — Max プランで利用する Claude モデル(最も軽量なインストール)、その Claude シムに同梱のローカルモデルを自動フォールバックとして組み合わせる構成、ChatGPT プランで GPT-5.6 モデルを使う同様の 2 構成(Codex CLI 経由)、あるいはプランを一切必要としない同梱のローカルモデル単体、という選択肢から選べます。その後スタックを起動し、選択したクライアントの接続を設定し(セッション開始時のブリーフィングフック — 毎回のセッションでメモリループのガイダンスを提供します — と、MCP トランスポートの登録)、デーモンのヘルスチェックを行います。冪等なので、いつでも再実行できます。`--extractor <mode>` で抽出器の構成を切り替えられます。

デーモンが起動していれば、Claude Code の**プラグイン**が、セッション開始時のメモリブリーフィング、常設のメモリループガイダンス、そして `/dream` と `/memory-status` コマンドを追加します — MCP サーバー自体はインストーラーが登録するため、プラグインがツールを二重に登録することはありません:

```
/plugin marketplace add Pseudogiant-xr/Pseudolife-MCP
/plugin install pseudolife-memory@pseudolife-mcp
```

Codex — インストーラーのデフォルト(シムモード)は、Claude 向けと同じ stdio シムを配線し、Docker のティアでは `PSEUDOLIFE_MCP_NO_SPAWN=1` を設定したままにします。これにより、Codex セッションは同時に動いている Claude セッションのエピソードを引き継ぐのではなく、自分自身の識別情報を持てるようになります。具体的なコマンド、直接 HTTP 接続する代替手段、デフォルト以外のポートやトークンについては、[README — コーディングエージェントへの接続](../../README.md#wire-into-your-coding-agent) を参照してください。

## 仕組み

エージェントは作業しながら主張を 1 件ずつ保存します(`memory_store`、`memory_fact_set`)。セッションの合間には、**ドリーム**がストリームを正準的なファクト、グラフのリレーション、手続き的な教訓へと蒸留します。毎回のセッション開始時には、ブリーフィングが「メモリが確信を持てていない点」「過去の作業から得た教訓」「前回の作業の続き」を注入します。検索は連想ストアに対するセマンティック検索と正準ファクトストアを組み合わせるため、訂正済みの回答が古い回答に勝ちます。
