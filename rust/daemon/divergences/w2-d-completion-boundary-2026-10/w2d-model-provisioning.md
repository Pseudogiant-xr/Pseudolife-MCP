| `w2d-model-provisioning` | Runtime download and unpinned checkpoints (default provisioning closed by #1114) | Default provisioning is served since #1114 (B8, D4): `pseudolife-daemon provision models` installs the pinned bundle (the public Qwen3-Embedding-0.6B ONNX export and the ms-marco-MiniLM-L-6-v2 reranker, each file by compiled SHA256 and byte size in `model_provision.rs`) into the model cache (`PSEUDOLIFE_DAEMON_MODELS_DIR`, else `<data dir>/models`), and the Rust image runs it at first start. The default embedder is read only from that bundle (or `PSEUDOLIFE_DAEMON_ONNX_DIR`) and verified against the pins before loading (`embed.rs`, `onnx_artifacts.rs::resolve`): a missing or tampered file refuses readiness with the repair command. The reranker comes from the bundle or `PSEUDOLIFE_DAEMON_RERANK_DIR`, verified against the same pins (`rerank.rs`); a failed load disables reranking with a logged line, and store and search remain available. What still differs: Python loads any configured checkpoint by name through SentenceTransformers and CrossEncoder (`CrossEncoder(model_name)` may fetch an uncached one from the Hugging Face Hub), while the Rust daemon never downloads at load time, takes a non-default embedding model only from a local directory or the Hub cache without a pin, and reranks only with the pinned cross-encoder (`memory.reranker.model_name` is only logged). No claim is made for arbitrary exported checkpoints. Provisioning through the installers and release-mode `update` is B11. |
