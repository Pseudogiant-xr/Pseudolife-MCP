# Python-to-Rust review checklist

Use this page with [PORTING.md](PORTING.md) for each frozen port boundary.
It collects existing rules and regression questions; it changes no admission,
comparison or acceptance policy. Record the actual producer, oracle/runtime,
candidate and exercised cases. Source preparation is not executable parity.

| Check | Adversarial questions and existing source anchors |
|---|---|
| JSON serialization | Which producer selects separators, escaping, null/default handling and numeric admission? Do absent, null, false and empty values remain distinct? Can an ignored field carry a refused value? HTTP `_send_json` uses `json.dumps(..., default=str)`; sent preserves exact response bytes, while hooks and lease have separately scoped admission rules. Do not transfer a strict parser or a parsed-object comparator between them. See [types and serialization](PORTING.md#types-and-serialization), [hook substitutions](PORTING.md#briefing-and-prompt-hook-producer-substitutions), [web/api.py](../pseudolife_memory/web/api.py) `_send_json`, and [sent_json.rs](shim/src/sent_json.rs) `encode`. |
| Float repr and integer domains | On a byte surface, are `-0.0`, integral floats, exponent thresholds (`1e-4`, `1e-5`, `1e15`, `1e16`) and exponent sign/width preserved? What admits non-finite values here? The `python_float_spelling` test in `sent_json.rs` is a scoped source control, not proof for every float. Has a bool been mistaken for an integer, or a large integer narrowed before decimal conversion? The HLC trial's arithmetic succeeded while observation packing failed. See [trial corrections](PORTING.md#disposable-trial-corrections), [float/ranking parity](PORTING.md#floating-point-and-ranking-parity), and [sent_json.rs](shim/src/sent_json.rs). Default comparison is exact; an accepted named score tolerance never permits changed IDs or ranking. |
| Dict order | Is this typed SDK field order, opaque producer insertion order, database-observed JSONB order, or an explicitly semantic object comparison? Arrays retain order and multiplicity. Would sorting or parse/reserialize hide changed bytes or duplicate keys? Stdio preserves numeric spelling and key order outside named spans; sent retains database order. See [types](PORTING.md#types-and-serialization), [stdio comparison](PORTING.md#phase-1-stdio-comparison), [measurement rules](PORTING.md#measurement-and-acceptance), and [wire_json.rs](shim/src/wire_json.rs) `shape_result`. |
| str and bytes | Where are bytes decoded, replaced, escaped or kept as an OS string? Are Unicode whitespace, casefold/NFC, control characters, astral escapes and platform newlines handled by the actual producer? Board's pinned Unicode correction found 129 casefold differences; a crate's Unicode version is not interchangeable. Invalid argv has separate Unix surrogateescape and Windows UTF-16 handling. No global LF or Unicode normalization follows. See [platform/Unicode rules](PORTING.md#unsafe-code-and-dependencies), [CLI contract](PORTING.md#phase-2-cli-contract), [argv.rs](shim/src/argv.rs) `python_repr`, and [unicode14.rs](shim/src/board/unicode14.rs). |
| datetime | Is the field a Unix numeric timestamp, local display, datetime `default=str`, HLC or cursor? Do unit, numeric type, timezone, fractional flooring and ordering survive? Are any allowed clock changes limited to named paths with each arm's own bounds? Sent datetime fixtures are supplemental producers, not SQL-column claims; lease's Chrono local-zone and extreme-list dispositions stay scoped. See [types](PORTING.md#types-and-serialization), [lease diagnostics](PORTING.md#lease-diagnostic-boundaries), [final lease boundary](PORTING.md#final-lease-core-comparison-boundary), and [measurement rules](PORTING.md#measurement-and-acceptance). |
| Exceptions to `Result` | Does each Rust error preserve the boundary's CLI exit/streams, HTTP status/body or MCP code/data/message, including pinned diagnostics? Are invalid input, auth, unavailable state and transport failure still distinct? Is an observer/serializer failure reported as a harness failure rather than an oracle exception or successful empty result? A traceback policy applies only to its named instances and fields. See [errors/recovery](PORTING.md#errors-and-recovery), [trial corrections](PORTING.md#disposable-trial-corrections), and [lease diagnostics](PORTING.md#lease-diagnostic-boundaries). |
| asyncio to tokio | At each await, who owns the child, task, socket, body, lock and cursor update? On disconnect, timeout, EOF or cancellation, is owned work cancelled and joined/reaped, and can the next ordinary operation succeed? Do frame order and multiplicity follow the specific observed-order rules? The first-frame callback follows successful write **and flush**; a failed flush starts no update. See [errors/recovery](PORTING.md#errors-and-recovery), [spawn/update boundary](PORTING.md#evidence-and-ownership), [stdio ordering](PORTING.md#phase-1-stdio-comparison), [web/api.py](../pseudolife_memory/web/api.py) `_wait_while_connected`, and [wire_json.rs](shim/src/wire_json.rs) `output_after_first_frame`. |

Add a rule for every escaped regression, with its producer and rejecting control.

Retain raw failures and rejecting controls beside successful captures. Existing
tests remain unchanged; when they are silent, record the Python behavior and
coverage gap before porting it. A historical receipt, source test or compiling
translation does not certify a later head. Apply the existing platform proof,
exact-head CI and independent review requirements in
[measurement and acceptance](PORTING.md#measurement-and-acceptance).
