### Fixed (2026-10-20 — Linux doorbell cleanup no longer fails when an unrelated process exits mid-scan)

- The Rust shim's Linux cleanup for a cancelled doorbell queue proves its process group is dead by reading every `/proc/<pid>/stat`. A process anywhere on the host that was reaped between the scan's open and read made the kernel answer `ESRCH` ("No such process"), and the cleanup reported that as a failure although the group was gone. `ESRCH` on that read now counts as absence, the same as a missing `/proc` entry, so a busy host no longer makes a correct cleanup fail. The leader's own identity reads still fail closed. This was the cause of the intermittent `cancelled_group_fences_low_priority_orphan_before_reaping_leader` failure on master's Linux Rust job (2026-10-19), which the local WSL loop reproduced under process churn.
