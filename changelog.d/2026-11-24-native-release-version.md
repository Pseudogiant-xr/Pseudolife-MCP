### Changed (2026-11-24 — the release version has a native home that outlives the Python package)
- The release version is now read from the native client's own crate, `[package] version` in `rust/shim/Cargo.toml`, through one reader, `rust/ci/release_version.py`. Its `check` command requires every field a version cut writes to equal it, and names the first that differs. `pyproject.toml` counts as one of those fields while the wheel is still published.
- The release workflow's `guards` job compares the release tag with that version and runs the same check before anything builds. The native asset steps, the version pins in `tests/test_plugin_packaging.py` and `tests/test_atlas_currency.py`, and the write-path harness's hook scenarios read the same version. The version cut still edits the same files.
