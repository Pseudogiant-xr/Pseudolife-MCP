### Fixed (2026-10-30 — a revoked or rotated token is named when a session starts)

- A machine whose token the daemon no longer accepts (revoked, rotated away, or never issued for it) used to start its memory sessions without a word: the shim's startup check, `/health`, needs no token, so only the model's first tool call met the refusal. The shim's startup instructions fetch, already its one authenticated request, now reads a 401 or 403 (or the daemon's revoked-token refusal) for the bearer it holds as a rejected token: it writes one line to stderr, which MCP hosts log, and puts the same line at the top of the session's instructions, naming the daemon URL and the fix (`pseudolife-mcp invite <name>` on the daemon host, then `pseudolife-mcp pair <url> --read-code` on this machine). The session keeps serving, and each tool call still returns the existing -32004 refusal. A network error, a timeout or a 5xx at that fetch, a shim with no credential and a daemon that is down keep their current behaviour, and no request or wait is added at startup. The Python and Rust shims print the same text.
