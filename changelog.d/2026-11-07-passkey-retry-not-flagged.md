### Fixed (2026-11-07 — a retried passkey-signed request no longer flags the key as cloned) [#1361]
- When a browser sent the same signed request twice, for example a retry after a lost answer, the second one was refused by the signature-counter check, and the maintainer passkey was flagged "sign count went backwards" as if it had been cloned. This affected keys that keep a counter (most hardware keys). Both daemons now spend the challenge before they compare the counter, so the retry is refused as already used and the key stays unflagged. A counter that really went backwards on a new challenge is still refused and flagged.
