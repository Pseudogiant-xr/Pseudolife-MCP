### Added (2026-10-19 — merge batches of ready pull requests)
- `python ops/integrate.py build` merges every open pull request labelled `ready-to-batch` into one `integrate/<date>-batch-N` branch with `git merge --no-ff`, in the order the label was applied, then pushes it and opens the batch pull request with each member's merged head, review link and CI. A member that conflicts is dropped, not resolved: the merge is aborted, the pull request gets a comment naming master or the member it collided with, and its label is removed. `--dry-run` merges on a detached HEAD and pushes, opens and comments on nothing. It refuses to run with uncommitted tracked changes, off `origin/master`, or while another batch is open, and never force-pushes.
- `python ops/integrate.py status` lists the labelled pull requests in batch order with whether each head merges cleanly into master, its CI and its review decision.
- A batch now runs the local WSL full suite on its head before CI, a red batch is bisected locally and the culprit dropped, and the batch pull request merges with a merge commit so its members show as merged (`CLAUDE.md`, `docs/dev/merge-batches.md`).
