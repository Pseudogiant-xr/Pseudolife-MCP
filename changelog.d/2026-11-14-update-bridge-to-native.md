### Changed (2026-11-14 — an update can move a Python client to the native client, when you ask for it)
- `pseudolife-mcp update` can now move a machine from the Python client to the native client in one run, and in this release it does so only when you ask. Set `PSEUDOLIFE_SHIM_ENGINE=native` before you run the update. An installed Python updater (0.23.x) then hands this release's client steps to its new Python runtime, and that runtime moves the machine. It downloads this release's native archive for the platform and its `SHA256SUMS` over HTTPS from the GitHub release (or `PSEUDOLIFE_NATIVE_ARCHIVE_URL`, the same override the native installer reads), verifies the digest, checks that the binary runs, and runs the native updater's client steps in its place. The native updater then installs the native runtime, activates the native launcher and moves the client registrations to it. No installer rerun is needed.
- Without the setting, the update keeps the Python client and says in one line how to move. The move is opt-in because the native client does not yet run everything the Python client does: interactive `connect`, most `tunnel` commands, `doctor` on a machine with a tunnel, `expose tailscale` / `off` changes, the Console sign-in on macOS, and a bank `move`. A machine already on this release's Python client moves later with `PSEUDOLIFE_SHIM_ENGINE=native pseudolife-mcp update --clients-only`.
- Nothing changes when the release has no native client for the platform, the download or digest check fails, the binary does not run here (an old glibc, for example), or `PSEUDOLIFE_SHIM_ENGINE=python` is set. One line says why the Python client was kept, and the client steps finish in Python as before. Once the native updater has started, its result is the run's.
