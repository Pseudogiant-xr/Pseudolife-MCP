### Fixed (2026-11-06 — Board mail wakes idle sessions on the native client runtime)
- With the native (Rust) client runtime, board mail never woke an idle Claude Code session on Linux or macOS. The Stop hook wrote its listener records (`<key>.wake`, `<key>.<token>.wake-armed`) and `<key>.seen` under the user's umask, usually 0644, and the native shim accepted only owner-only (0600) files, so the daemon was never told a listener was armed and answered `no_path`. The Python runtime was unaffected.
- The plugin hooks now write every file beside the digest 0600 (`umask 077` inside the handler scripts; `hooks.json` is unchanged, so Codex users re-approve nothing). Updating the plugin alone fixes sessions on the 0.22.0 native runtime.
- The native shim accepts a marker that this user owns and that is not group- or world-writable, so 0644 markers from older hooks work. It refuses a marker another user owns or others can write, which could forge or suppress a wake, and prints one line naming the path and the fix (`chmod 600 <path>`, or remove it).
