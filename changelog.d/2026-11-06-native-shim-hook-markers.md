### Fixed (2026-11-06 — Board mail wakes idle sessions on the native client runtime on Linux and macOS)
- With the native (Rust) client runtime on Linux or macOS, board mail never woke an idle Claude Code session; the Python runtime was unaffected. The Stop hook wrote its listener records (`<key>.wake`, `<key>.<token>.wake-armed`) and `<key>.seen` under the user's umask, usually 0644, and the native shim accepted only owner-only (0600) files, so the daemon was never told a listener was armed and answered `no_path`.
- The plugin's handler scripts now create every new file beside the digest 0600 (`umask 077` inside the scripts; `hooks.json` is unchanged, so Codex users re-approve nothing). Files a hook rewrites in place, such as `ledger.log` and `.mark`, keep the mode they already had. Updating the plugin alone fixes sessions on the 0.22.0 native runtime.
- The native shim accepts a marker that this user owns and that is not group- or world-writable, so 0644 markers from older hooks work. It refuses a marker another user owns or others can write, which could forge or suppress a wake, and prints one line per directory and marker kind naming the path and the fix (update the plugin, or `chmod 600 <path>`). Its stale-marker sweep now removes old hook-written markers too.
- Not fixed on Windows: the native shim still requires a protected owner-only ACL there, which files written by Git Bash or PowerShell do not have, so the Windows native wake stays open (#1326).
