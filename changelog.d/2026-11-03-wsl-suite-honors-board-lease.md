### Fixed (2026-11-03 — A full suite waits for another holder of its board lease)
- A full test suite that held its local lock started even while the board showed its lease (`full-suite`) held by someone else, printing only that it "carries on". A WSL suite cannot see a Windows-side `pseudolife-mcp lease run full-suite` lock, so a native build and a WSL suite ran on the same machine at once. Once a full run holds its local lock it now waits, in the board's queue order, until the board grants it the lease, naming the holder and its purpose about once a minute; `PSEUDOLIFE_SUITE_LOCK=fail` exits instead. The board decides when a hold has lapsed. A record under the run's own lock-directory label while no `lease hold` of the lease runs here, or the enclosing `lease run full-suite -- python -m pytest tests/` the run was started by (named in `PSEUDOLIFE_LEASES_HELD`, its lock not free), does not stop it; fail mode does not wait for a board that stops answering, and without a bearer the local lock alone still rules. The recorded run time starts once the board admits the run. `lease hold` is unchanged.
