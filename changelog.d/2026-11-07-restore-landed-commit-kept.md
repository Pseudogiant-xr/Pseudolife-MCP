### Fixed (2026-11-07 — a restore whose commit landed is no longer written back to retired by a full save)
- After a world or lesson restore whose database COMMIT succeeded but whose reply was lost, the Python engine undid the restore in memory, so a later full save (`MemoryService.save()` or `flush()`, which rewrite the whole table from memory) wrote the restored value back to retired while the restore's audit row stayed. The engine now undoes a restore only when its transaction certainly rolled back; when the COMMIT itself failed it reads the bank: a restore that landed is served and the call succeeds, one that did not is undone, and when the bank cannot be read the restore is kept, so a save writes what was asked for. The daemon's own exit save writes only changed slots and was not affected; the Rust daemon has no full rewrite and serves the bank's state from the next call.
