### Fixed (2026-11-11 — the Rust daemon image serves the Console's Markdown notice as Markdown)
- The Rust daemon image served `/ui/vendor/README.md` as `application/octet-stream`, which browsers treat as a download, while the Python image served `text/markdown; charset=utf-8`. The Rust daemon looked `.md` up only in the platform MIME table, and its image has none (no `/etc/mime.types`). It now uses the platform table's mapping when there is one and otherwise Python 3.12's builtin `text/markdown`, the same order CPython 3.12 uses. Every other file in the shipped Console build already had the Python image's type; `.webp` keeps using the platform table, as CPython 3.12 does, which in both images means `application/octet-stream`.
- The static parity harness now compares the Rust daemon against the Python 3.12 image's types even when its Python oracle is older (CI runs 3.11, which has no builtin `.md` type), and a Rust unit test pins the shipped image's type for every file extension in the Console build with no platform table, so a new asset type or a regression fails the test.
