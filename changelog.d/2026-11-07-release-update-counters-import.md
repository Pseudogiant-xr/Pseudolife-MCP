### Added (2026-11-07 — release-mode update imports legacy counters before switching to Rust)
- `pseudolife-mcp update --engine rust` on a Python host whose bank still keeps its CMS counters in `memory_state/weights.pt`, or is below schema v57, no longer refuses. It first checks that the Rust image for the target pulls, then updates to the Python daemon at the target release, whose startup imports the counters into `cms_counters`, then switches to the Rust daemon. Each step is its own backup, rollback tag and health gate, in both the Python and native updaters; a `--rollback-tag` suffix gets `-pre-import` on the first step so the two tags stay apart, and the `--json` report keeps the first step's rollback under `rollback.before_import`. A low `--keep-rollbacks` can prune the first step's tag during the second.
- If the Python daemon did not import the counters, the update stops there, on Python, exits 1 and says how to recover (an unreadable `weights.pt` is moved aside, after which the counters restart from zero). A host already on the Rust daemon with unimported counters, or a bank whose schema cannot be read, is refused with nothing changed. Checkout-mode `update --engine rust --checkout` still refuses such a bank, naming the same fix.
