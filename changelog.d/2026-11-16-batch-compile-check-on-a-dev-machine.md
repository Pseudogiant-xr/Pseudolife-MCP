### Changed (2026-11-16 — a batch's compile check runs on a dev machine)
- `python ops/integrate.py build` runs its Rust compile check (`cargo check --workspace --all-targets --locked`) on the dev machine that a private `~/.pseudolife-mcp/locks/rust-check.remote` names, instead of on the host that runs `build`. `build` sends the batch to that machine as a git bundle over ssh, so nothing is pushed before the operator's publication check. The far half, `ops/rust-check-remote.ps1`, refuses a bundle whose head is not the batch head, runs one locked gate worktree with its own target directory, and removes its private ref and bundle; it sweeps any that a killed run left. It refuses, as not run, while a full suite holds the machine or its drive has under 8 GB free. A machine that cannot be reached, is busy or has no cargo is recorded as a check that did not run, and `open` refuses it. Nothing falls back to the local host: only `PSEUDOLIFE_RUST_CHECK_WHERE=local` runs the check there. The batch body names the machine by its role. Without the file, the check runs locally as before.
