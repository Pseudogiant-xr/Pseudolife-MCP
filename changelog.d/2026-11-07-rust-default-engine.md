### Changed (2026-11-07 — the Rust daemon becomes the default Docker engine)
- A new Docker install (`ops/install.sh`, `ops/install.ps1`) runs the Rust daemon unless `--engine python` / `-Engine python` says otherwise; that choice is recorded, so later updates keep Python (a choice that cannot be written warns and the install still succeeds). With no `--engine`, an install takes the Python daemon, saying why, when it has no bearer token (including a host that cannot install the shim and so mints none), when its release publishes no Rust image or the models cannot be downloaded, or when the bank already exists (the next attended update moves that bank after its own checks). An explicit `--engine rust` without a bearer refuses before any container starts.
- A release-mode `pseudolife-mcp update` moves a host that never chose an engine to the Rust daemon when the target release publishes its image (`docker manifest inspect`), through the same checks, verified backup, rollback tag and health gate as `--engine rust`. Every run does this except the scheduled `--unattended` one; a run with no terminal (a script, ssh, an agent's shell) moves the host too. Runs with `--no-backup` or `--allow-auth-change` keep the engine. A host chose when it runs Rust, carries an engine activation, or recorded an accepted selection or an explicit `--engine python`; an unreadable or corrupt choice file keeps the engine and says so.
- Before it downloads the models or backs anything up, the move runs the new `pseudolife-daemon check-config` on the target image (the daemon's working directory, configuration environment without credentials, and existing mounts read-only; no network, no bank), so a configuration the Rust daemon refuses at startup, such as a non-default reranker, an embedding model it cannot load or an unsupported module layout, keeps the Python daemon instead of failing the switch. An explicit `--engine rust` refuses such a configuration before the backup. The move never blocks an ordinary update: if anything refuses before the backup, the update removes the image and model volume it added for the move, warns with the refusal and its fix, and continues on Python. `update --engine python` switches back and records the choice, also when there is nothing to deploy.
