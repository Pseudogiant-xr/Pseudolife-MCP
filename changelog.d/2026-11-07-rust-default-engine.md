### Changed (2026-11-07 — the Rust daemon becomes the default Docker engine)
- A new Docker install (`ops/install.sh`, `ops/install.ps1`) runs the Rust daemon unless `--engine python` / `-Engine python` says otherwise; that choice is recorded, so later updates keep Python. With no `--engine`, an install takes the Python daemon, saying why, when it would have no bearer token, when its release publishes no Rust image or the models cannot be downloaded, or when the bank already exists (the next attended update moves that bank after its own checks).
- An attended release-mode `pseudolife-mcp update` moves a host that never chose an engine to the Rust daemon when the target release publishes its image (`docker manifest inspect`), through the same checks, verified backup, rollback tag and health gate as `--engine rust`. A host chose when it runs Rust, carries an engine activation, or recorded an accepted selection or an explicit `--engine python`. The move never blocks an ordinary update: if it refuses before the backup (no bearer, a counters import still pending, a newer bank schema, a pull that fails), the update continues on Python and says why. It is not offered to unattended runs or with `--no-backup`. `update --engine python` switches back and records the choice, also when there is nothing to deploy.
