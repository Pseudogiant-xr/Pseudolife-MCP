### Fixed (2026-11-27 — a dead database connection no longer hangs the board)
- The daemon's board connection now sends TCP keepalives after 10 s idle (every 5 s, three tries) and, on Linux, caps unacknowledged writes at 30 s, the values the principal refresher already used. A connection whose PostgreSQL host or a NAT vanished without a reset now fails in about 30 s and the next board call reconnects, instead of every board call hanging behind it until the operating system gave up (about 15 minutes on Linux). On Windows the system's keepalive probe count applies, and only Linux caps a request already in flight.
- The memory writer connection gets the same protection, matched to the server-side keepalive its writer lease already sets (60 s idle, every 10 s, three tries, and a 90 s cap on Linux), so a short network pause still heals by itself instead of ending in a reconnect the old session refuses the lease.
- The board connection also bounds each statement at 60 s, unless the database or role already sets a tighter `statement_timeout`, which is kept. Reads that already set a 5 s bound keep it. The writer connection sets no statement timeout.
