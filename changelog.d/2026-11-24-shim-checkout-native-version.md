### Changed (2026-11-24 — the native client's checkout mode reads the release version from its own crate)
- The native client's installer engine (`pseudolife-mcp installer engine`) and checkout-mode `update` read a checkout's release version from `[package] version` in `rust/shim/Cargo.toml`, no longer from `pyproject.toml`, and their refusals name that file. This is the same field that `rust/ci/release_version.py` reads; that reader for the release tooling is added by #1922.
- A directory counts as a checkout when its `rust/shim/Cargo.toml` names this repository's crate (`pseudolife-stdio`) or, for a checkout from before this change, when it has `pyproject.toml`. A manifest that cannot be read or is not valid TOML is refused as a broken checkout. The refusal names the file, its cause and the repair. A checkout with no `rust/shim/` at all predates the native client crate and is told to update the checkout. A current checkout whose manifest was deleted is told to restore it. A manifest with no plain version names the line it needs and its repair; only a version that is not a plain release still points to a release tag. So checkout detection keeps working once the Python package and its `pyproject.toml` are gone.
