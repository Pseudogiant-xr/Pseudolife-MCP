### Fixed (2026-11-27 — the "daemon is down" advice no longer recreates the daemon on the retired Python image)
- When no local daemon answers, the shim's stderr note, the instructions it serves to the client's agent, `pseudolife-mcp serve` and the plugin's `/memory-status` told users to run `docker compose -f ops/docker-compose.yml up -d`. That base file names the Python daemon image, so on a Rust host it recreated the daemon on the retired engine. They now say `docker start pseudolife-mcp-postgres pseudolife-mcp-daemon`, which starts the existing containers on the image they already run. The stderr note also names the extractor sidecar for installs that run it. A restore or move that finds no container now says to recreate it the way the bank was deployed (the installer from its original checkout and env file, or the stack manager's own redeploy), instead of `docker compose up -d` in the install directory. The dreaming guide's step for applying an `ops/.env` change names `pseudolife-mcp update --reinstall --daemon-only --tag <version>` (a checkout reruns `ops/update.*`), and the configuration guide sends a bearer change to its explicit handover section, instead of a Compose `up` from the base file.
