### Fixed (2026-11-27 — the "daemon is down" advice no longer recreates the daemon on the retired Python image)
- When no local daemon answers, the shim's stderr note, the instructions it serves to the client's agent, `pseudolife-mcp serve` and the plugin's `/memory-status` told users to run `docker compose -f ops/docker-compose.yml up -d`. That base file names the Python daemon image, so on a Rust host it recreated the daemon on the retired engine. They now say `docker start pseudolife-mcp-postgres pseudolife-mcp-daemon`, which starts the existing containers on the image they already run. The dreaming guide's "apply an `ops/.env` change" step now says `pseudolife-mcp update --reinstall --daemon-only`.
