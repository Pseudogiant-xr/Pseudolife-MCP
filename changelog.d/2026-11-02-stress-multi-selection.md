### Changed (2026-11-02 — Stress loops can name several rows or scenarios at once)
- A stress dispatch (`rust.yml` mode=stress) can now name several space-separated `row:` items, or several `scenario:` items, instead of exactly one. Every iteration runs each item in turn, so stress-testing N rows costs one set of runner jobs (20 by default) instead of N sets. This matters because hosted Windows concurrency is the project's CI bottleneck.
- Each item still runs alone, as its own harness process, with the binary, flags and environment its required lane uses. An iteration passes only if every item compared at least one case. The iteration's row and the stress report list each item's own result, so a failing row or scenario is named.
- `plan` refuses a selection that mixes rows with scenarios or other kinds, names an item twice, or includes a scenario that needs the debug loopback-bind build. Each refusal names the item. Single-item selections behave and record exactly as before.
