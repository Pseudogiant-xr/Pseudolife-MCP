### Added (2026-10-31 — The client-only installer offers the daily client update job)

- A client-only install (`ops/install.sh` on Linux, `ops/install.ps1` on Windows) now offers, near the end of the run, to keep the machine's clients on the daemon's release with the daily job `pseudolife-mcp update --schedule` installs, instead of leaving that step to the docs. It asks once, default no; `--client-update-schedule ask|yes|no|HH:MM` / `-ClientUpdateSchedule` answers in advance, and `yes` uses 04:30, an hour after the documented 03:30 daemon-host job, so an overnight daemon update reaches the clients the same morning. The installer runs the installed shim's own `update --schedule HH:MM --daemon-url <url>`; a run with no terminal skips it with one line naming that command; a rerun leaves a job already in place alone in one line (naming the command that moves it when it follows another daemon); a refusal from `--schedule` is a warning and the install still completes. A daemon-host install is never offered it and refuses the flag's `yes` or a time; macOS, which has no scheduler here, is not offered it.
