### Changed (2026-11-24 — every `pseudolife-mcp tunnel` command on the native client now answers or says why not and what to run instead)
- The native client no longer stops any `tunnel` command with the generic "mode 'tunnel' is deferred in this candidate" line (exit 1), and `tunnel` is no longer a deferred mode. `tunnel start`, `tunnel doctor`, `tunnel service ...`, `tunnel setup --start` and `tunnel setup --open-browser` are not part of the native client: they are refused with exit 2 and what to do instead, which is `tunnel run` with the same `--profile` and `--profile-dir` in a terminal you keep open (ended with `tunnel stop`), `tunnel status`, or the Platform pages to open. A service the Python client registered is managed with the service manager's own commands, which `pseudolife-mcp update` prints.
- Argument mistakes name the option at fault and point to the new `pseudolife-mcp tunnel --help` and `tunnel <command> --help`. `--option=value` is accepted as the same option. A positional argument or an unknown command word is never echoed, since it may be a key typed in the wrong place.
- Guided setup is refused with the explicit `--daemon-url` and `--token-file` to pass. A setup value the client does not read (a daemon URL or expiry spelling, a UNC token path) is named by its option without echoing it. A saved profile, key, verification challenge or refresh file in a form the client does not read is named with its path and the fix, as are verification of a launch another client started, a process record whose launch cannot be told, and a Windows key the session cannot unseal.
- A profile whose autostart the Python client approved no longer blocks `tunnel setup`: settings edits, a first key import, a key renewal and `--restore-key` / `--discard-previous-key` now proceed for it as for any other profile. `tunnel setup` can also change the settings of a profile whose runtime key is saved. Such an edit asks for consent again on any connection or access change; it refuses with "stop the tunnel first" while a launch or a key renewal holds that profile's locks, refuses while a process record exists (naming it) or when a key appears during the handshake, and changes the saved key's expiry only through a renewal of that key.
