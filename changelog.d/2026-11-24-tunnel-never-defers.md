### Changed (2026-11-24 — every `pseudolife-mcp tunnel` command on the native client now answers or says why not and what to run instead)
- The native client no longer stops any `tunnel` command with the generic "mode 'tunnel' is deferred in this candidate" line (exit 1). Forms it does not run yet (`tunnel start`, `tunnel doctor`, `tunnel service ...`, `tunnel setup --start` and `tunnel setup --open-browser`) are refused with exit 2 and the command to use instead: `tunnel run` in a terminal you keep open, `tunnel status`, or the Platform pages to open. `tunnel` is no longer a deferred mode.
- Argument mistakes name the option at fault and point to the new `pseudolife-mcp tunnel --help` and `tunnel <command> --help`. `--option=value` is accepted as the same option.
- Guided setup is refused with the explicit `--daemon-url` and `--token-file` to pass. A saved profile, key, verification challenge or refresh file in a form the client does not read is named with its path and the fix, as are verification of a launch another client started and a Windows key the session cannot unseal.
- `tunnel setup` can now change the settings of a profile whose runtime key is saved or whose autostart was approved, asking for consent again where a connection or access changes. A process record still refuses the change, now naming the record.
