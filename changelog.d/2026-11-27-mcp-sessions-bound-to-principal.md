### Changed (2026-11-27 — MCP sessions belong to the principal that opened them, and idle ones are dropped)
- The daemon's `/mcp` endpoint now ties each session to the principal whose bearer opened it: a request, event stream or `DELETE` that carries the session id under another principal gets `404 Session not found`, as for an unknown id, and leaves the session alone. Tool calls already took their identity from each request's own bearer; this keeps one principal from ending or attaching to another's session.
- A session with no request for 12 hours and no open event stream is dropped (the client opens a new one, as MCP clients do on a 404), and each principal keeps at most 1,000, its own least recently used going first, so no principal can push out another's. A session that has an open event stream or a request in flight is evicted only after the principal's idle ones, and an opening request that is refused never displaces anyone. Tier overrides (one per principal or writer) are capped at 10,000 beside their existing 12-hour expiry, the oldest going first.
