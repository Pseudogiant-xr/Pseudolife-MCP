### Fixed (2026-11-25 — the Rust regression gate accepts the reproducible Qwen server it starts)
- The Rust eval drivers' model check accepts a llama.cpp server that names the pinned model file by its full path. The reproducible Qwen server starts with `-m <path>` and no alias, and engine b10488 then reports that path in `/v1/models` and in every chat response, whatever model the request named. So the gate refused the server it had just started, after building all 78 contexts. The check now treats a GGUF file named by a path and by its file name as the same model. Every other model id still has to match exactly. Another file, or a name that only contains the pinned one, is still refused, and the error names both files, never the directory. An error prints any filesystem path by its file name (a GGUF id, or one that starts with `/`, `\`, `~` or a drive letter), and every other id in full, so two hub ids that differ only in their organisation stay distinct. `lme_rejudge.py` uses the same rule, so it still refuses the primary run's judge when one run pinned the GGUF's path and the other its file name.
