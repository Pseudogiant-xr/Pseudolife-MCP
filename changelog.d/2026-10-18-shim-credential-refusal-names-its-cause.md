### Fixed (2026-10-18 — a refused token file says why, and how to fix it)

- When the shim cannot use its token file, the error on every MCP call now names the real reason, the file, and the one fix, instead of "restore the configured credential" for every case. A file that lost its owner-only permissions (a plain rewrite during a token rotation does this) says so and gives the command that restores them: `icacls "<file>" /inheritance:r /grant:r *S-1-3-4:F` on Windows, `chmod 600 <file>` elsewhere. A missing file, an unreadable one, a link or junction, a redirected directory and a malformed token each name their own fix. The error's data carries the same `reason`, `recovery` and `credential_file`, and never the token. A token file replaced in the middle of a call now says the credential changed and to retry it.
- Pseudolife's own token-file writer (used by Codex setup, the Claude Desktop registration and unattended updates) now replaces an existing file you own whose permissions are broader than owner-only, instead of refusing it: the new file is owner-only, so writing it repairs them. Links, hard links, non-files and files another account owns are still refused.
