### Added (2026-11-07 — the Docker installers can install the Rust daemon)
- `ops/install.sh --engine rust` and `ops/install.ps1 -Engine rust` install the Rust daemon from the image the checkout's release publishes. They pull it and provision its pinned models into the `pseudolife_rust_models` volume before any container starts, so a missing image or a failed download refuses with nothing started and names `--engine python`. The selection is recorded only after the daemon reports healthy, in the same form `pseudolife-mcp update` verifies, so later updates keep Rust.
- A rerun keeps the engine installed, with no flag needed, and leaves an unchanged stack untouched. Before, the installer's Compose step and its change check used only the base Compose file, so a rerun on a host that `update --engine rust` had switched would recreate the daemon from it. Naming the other engine on an existing install switches it after the install through `pseudolife-mcp update --engine`, with its backup, rollback tag and health gate. A new install without the flag still gets the Python daemon, and `--client-only` refuses `--engine`.
