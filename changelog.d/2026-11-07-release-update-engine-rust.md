### Added (2026-11-07 — release-mode update can select the Rust daemon)
- `pseudolife-mcp update --engine rust` now works in release mode on a Docker host, for a release that publishes the `ghcr.io/pseudogiant-xr/pseudolife-daemon-rust:<version>` image. It keeps the bank, `/data` volume, port and bearer settings: it first imports the counters of a bank that never imported them (below), pulls and probes the image, installs the pinned models into their own `pseudolife_rust_models` volume at `/models` while the running daemon keeps serving, backs up the bank and `/data` (both must be complete), tags the running image for rollback, recreates only the daemon, and records the selection only after the new daemon passes its version, schema and authenticated-read check. If the release has no Rust image, the pull fails and nothing changes. An explicit engine change (`--engine`) never moves the clients.
- On a Rust host, `update` without `--engine` keeps Rust; if a release publishes no Rust image, that update stops at its pull, says the host keeps its current Rust daemon, and changes nothing. `update --engine python` switches back to the Python daemon on the same bank.
- The models live outside `/data`, so the roughly 2.4 GB of model files stay out of every backup. A daemon configured with its own `PSEUDOLIFE_DAEMON_ONNX_DIR` is left to provision its models itself.
- The package bundles `docker-compose.rust-ghcr.yml` beside its other Compose files, so a release update whose compose files are gone can still select Rust.
