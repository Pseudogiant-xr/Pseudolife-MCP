### Fixed (2026-11-23 — Codex setup works before Codex has ever been started) [#1897]
- The native client's Codex setup now creates the Codex home before it starts Codex, when that folder does not exist yet. This covers the installers' Codex credential and runtime-default steps, and every other step that starts `codex app-server`. The home is `~/.codex`, or the folder `CODEX_HOME` names, created with any missing parent folders. Codex refuses a `CODEX_HOME` that does not exist. On a host where Codex was installed but never started, setup used to stop there, leave Codex unregistered and make the installer exit 5. The folder is created the way Codex creates its own: on Linux and macOS its mode follows the umask, and on Windows its access is inherited from the parent folder. When the folder cannot be used, the refusal names the path and says what is in the way, and names the variable when `CODEX_HOME` set it.
- When Codex exits during the setup handshake, the recovery now gives its exit code and names the Codex program that was started, so the user can run it to see the error. An exit later in setup says to run `codex` to see the error. Neither tells the user to update Codex any more, because the client has no evidence that the Codex version is the cause. A setup reply the client cannot read still asks for a Codex update, but no longer says Codex exited.
