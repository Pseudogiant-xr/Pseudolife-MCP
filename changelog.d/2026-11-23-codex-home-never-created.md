### Fixed (2026-11-23 — Codex setup works before Codex has ever been started) [#1897]
- The native client's Codex setup (the installers' Codex credential and runtime-default steps, and every other step that starts `codex app-server`) creates the Codex home before it starts Codex when the folder does not exist yet. That is `~/.codex`, or the folder `CODEX_HOME` names, parents included. Codex refuses a `CODEX_HOME` that does not exist, so on a host where Codex was installed but never started, setup used to stop, the installer left Codex unregistered and exited 5. The folder is created as Codex creates its own: its mode follows the umask on Linux and macOS, and on Windows its access is inherited from the parent folder.
- When Codex exits before setup completes, the recovery gives its exit code and says to run `codex` to see the error it reports. It no longer tells the user to update Codex, which the client has no evidence for. A setup reply the client cannot read still asks for a Codex update, but no longer says Codex exited.
