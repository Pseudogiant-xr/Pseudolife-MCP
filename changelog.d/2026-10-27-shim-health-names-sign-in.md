### Fixed (2026-10-27 — the CLI shims' /health says when the CLI is signed out, and how to fix it)
- The Claude and Codex CLI shims now keep the CLI's own message when a call fails. They read both stdout and stderr, bound each stream separately and say when neither printed anything. Before this, an expired Claude Code sign-in answered `/health` with `{"status": "cli_error", "detail": "claude -p rc=1: "}`, because the CLI printed "Failed to authenticate: OAuth session expired" on stdout and the shim read only stderr.
- A failed health check whose message is a sign-in failure now answers 503 with `"status": "login_required"` and a `fix` naming the command to run on the shim host (`claude auth login` or `codex login`). Any other failure stays `"status": "cli_error"`. The daemon's probe still treats every 503 as primary-down.
