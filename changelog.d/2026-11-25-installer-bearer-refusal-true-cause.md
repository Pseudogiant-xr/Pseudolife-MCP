### Fixed (2026-11-25 — the installers' bearer refusal names fixes that work) [#1968]
- On a host with another release's unfinished Rust daemon container, all four installers now refuse with the container's own refusal (remove the container, then rerun) before the "Rust daemon needs its bearer token" refusal. Before, they named token fixes and an `--engine python` rerun that each led only to that second refusal. A new read-only helper step, `installer engine foreign`, gives that refusal without pulling or writing anything.
- On a host with an accepted Rust daemon and no bearer to come, `--engine python` (`-Engine python`) now gets a refusal that says the switch to the Python daemon needs the token too, because `pseudolife-mcp update` reads the Rust daemon with it first, and that the same rerun makes the switch once the token is set or can be minted. Before, the refusal named only token fixes and said nothing about leaving Rust. `update --engine python --daemon-only` with the bearer gone refuses and names the token, so it is not offered as a way around it.
- The Python-client installers (`ops/install.sh`, `ops/install.ps1`) now name `--no-token` (`-NoToken`) or `--transport http` as the cause when that is why no token can be minted, instead of missing pipx.
