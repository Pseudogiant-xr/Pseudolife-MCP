### Fixed (2026-11-26 — the extractor settings block in ops/.env names a step that applies an edit, without Python)
- The native client's extractor shim setup (`pseudolife-mcp extractor-shim install-autostart` and `extractor-shim config`, which the installers run for the `claude-only`, `claude-fallback`, `openai-only` and `openai-fallback` extractor modes) wrote a managed block into `ops/.env` whose first line said to apply an edit with `python ops/shim_autostart.py restart claude|codex`. A machine on the native client may have no Python. The first line now names a step that works there. On Linux it is `systemctl --user restart pseudolife-sonnet-shim.service` (Claude) or `pseudolife-codex-shim.service` (Codex), or the unit named at install with `--name`; the shim reads the file at every start. On Windows it names the scheduled task and the registration's own `pseudolife-mcp extractor-shim install-autostart` command, to run in PowerShell while that task is registered, written by `install-autostart` with this install's checkout or settings file, launcher, task name, logon type, startup timeout and receipt directory, so it can be run as it stands; a value with a typographic apostrophe is quoted as PowerShell reads it.
- On Windows, stopping and starting the scheduled task does not apply an edit: it stops only the PowerShell wrapper the task runs, and the shim that wrapper started keeps its port and its old settings. The registration's last line used to say "stop and start scheduled task"; it now names the same `install-autostart` command, which stops that shim and checks that the new one serves.
- Running `extractor-shim install-autostart` again no longer resets the shim's log path. It used to write its default log path into the settings whenever `--log` was not given, which undid an edited `PSEUDOLIFE_<KIND>_SHIM_LOG`; it now writes the default only when the settings name no log.
- A block written by the Python tool or by an earlier native release, and a block written on another platform, is still found and replaced on the next write, with its values kept. A comment that only resembles the marker is left alone. A bare `extractor-shim config` keeps the Windows line the registration wrote; where there is none, it writes a fixed line that names the command but does not guess its task name or logon type.
- A first block line with no last line before the next block or the end of the file now owns nothing: the stray line itself is dropped and the lines after it are treated as lines outside the block (the written provider's own `PSEUDOLIFE_<KIND>_SHIM_*` lines are moved into the block, as anywhere else in the file). `ops/shim_autostart.py` (a host moved back to the Python client) leaves the native first line behind that way, and the next native write used to fold everything up to the Python block into the shim block: comments were dropped and unrelated settings, the installer's own managed block included, were moved and requoted.
- The extractor-shim comment in `ops/.env.example`, which a first write copies into `ops/.env`, names the same steps and says which command applies to an autostart a Python-client install registered.
