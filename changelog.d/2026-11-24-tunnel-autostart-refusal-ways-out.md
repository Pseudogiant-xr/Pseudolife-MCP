### Fixed (2026-11-24 — the tunnel autostart refusal names ways out that stay true when the native client becomes the default)
- When a machine stays on the Python client because a tunnel is registered to start by itself, the refusal now says to rerun with `PSEUDOLIFE_SHIM_ENGINE=python` in place of any `PSEUDOLIFE_SHIM_ENGINE=native` to stay. Rerunning without `PSEUDOLIFE_SHIM_ENGINE=native` would move the machine once the native client is the default.
- The refusal now names the service manager's own commands for removing the autostart, which need no Python client: `systemctl disable --now`, deleting the unit and `daemon-reload`; `launchctl bootout` and deleting the plist; or `schtasks /End` and then `schtasks /Delete`. On Linux and macOS it also deletes the Python client's record of the service, without which that client's later `tunnel service` commands would refuse the profile. The Python client's `pseudolife-mcp tunnel service remove` command stays as the alternative.
- On a machine already on the native client, the removal it names for a registered task now ends the running tunnel before deleting the task; `schtasks /Delete` alone leaves the tunnel running.
- When the check could not run, the note now names removal commands only for a service carrying the product's owner marker that starts this machine's launcher, and says to leave any other service alone. It no longer tells the user to switch back to the Python client.
- An unattended run that keeps the client no longer says a later run will move it. It names the command a person runs: `PSEUDOLIFE_SHIM_ENGINE=native pseudolife-mcp update --clients-only`, labelled for PowerShell on Windows.
