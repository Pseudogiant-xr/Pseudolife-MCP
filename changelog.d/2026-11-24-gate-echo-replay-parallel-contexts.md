### Changed (2026-11-24 — the Rust regression gate can establish its baseline)
- The Rust regression gate's fixture replay accepts a write the daemon keeps as its standing value. That happens for a compression echo or a value that is equal after normalisation, and `memory_fact_set` answers `confirmed` on the same entity and attribute with the slot's previous value. Each such write is listed under `echo_confirmed` in `contexts.json` and the baseline candidate. Every other difference from the fixture's history still makes the run incomplete. The first authorised baseline run stopped at the first such write; a CPU replay of all 78 questions then found four (#1924).
- The gate builds its context cells several at a time (`-ContextWorkers`, sized by default to free memory, commit headroom and cores; a larger request is lowered to what free memory allows). Each daemon stays on one ORT thread, so the contexts are byte-identical to a serial build. The first failed cell stops the others at their next turn without a daemon log for each stopped cell, Ctrl+C is seen within a second, and each built cell prints a progress line. It also records every context before the model server starts, so the GPU is held only for answering and judging.
