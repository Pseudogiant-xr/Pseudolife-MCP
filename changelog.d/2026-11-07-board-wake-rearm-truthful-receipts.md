### Fixed (2026-11-07 — Board wakes survive a failed turn, and receipts say when a session is mid-turn)
- A Claude Code session whose turn ended on an API or sign-in error never re-armed its board-mail listener. Such a turn runs Claude Code's `StopFailure` hook, never `Stop` (2.1.318, measured 2026-11-07), so clearing mail waited until something else started a turn. On 2026-11-07 two decisions to a T3 Code delegated child waited 15 minutes behind a login expiry. The plugin now registers `stop-wake.sh stop-failure` on `StopFailure` (async and asyncRewake, like `Stop`). It arms the same watcher without asking the park gate, since a failed turn has nothing to park and a block would start another turn that may fail the same way.
- Codex users approve nothing again. Codex 0.167.0 skips the unknown `StopFailure` event: `hooks/list` shows no error and no new handler, and the existing handlers keep their trusted hash. A Codex that one day runs it gets a no-op (`lifecycle.ps1 -Event StopFailure`, or the script's Codex check). `ops/setup-codex-hooks.py` treats the event as optional.
- A send to an attached Claude Code session whose listener is down now answers `no_path` with reason `listener_rearming` instead of `listener_expired`. Its fallback says the session is open and usually working in a turn: each ring ends the watcher until the turn ends, so this is often a turn an earlier ring started. The queued ring fires when that turn ends, so no resend is needed. The fallback also names the host paths, T3 Code's thread send among them, for a turn that ended on an error or interrupt. Every `listener_expired` receipt to a T3 child on 2026-11-07 came mid-turn, and the conductor resent each one by hand. The Claude `fallback_paths` gain `t3_thread_send`.
- When the park gate blocks because mail rang after the session's park (now reason `rung_since_park`, before `not_updated_this_turn`), its text tells the session to read that mail first and then re-park. The plain "update your board status" request made a continuation re-park "waiting on you" with the answer still unread: the ring had landed two seconds before the gate asked.
- Python and Rust daemons both. Deploying needs the client step (release-mode `pseudolife-mcp update`, or `python ops/update_clients.py` after a checkout deploy), since the plugin's `hooks.json` and hook scripts changed. New sessions pick it up, while running ones keep the old hooks.
