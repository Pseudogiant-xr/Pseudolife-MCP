### Fixed (2026-11-28 — a first install that approves the Codex hooks finishes instead of exiting 5)
- On a first install, the installers set up the Codex hooks before they register the pseudolife-memory server with Codex. Until now the hook check then read the daemon with no token, so a daemon that needs one refused it. The installer said Codex setup was incomplete ("The memory daemon did not list its episodes; check daemon access", or "Hook setup failed (HTTPError)" from the Python client) and exited 5, although the hooks were installed and working. This hit every client-only or paired install that approved the hooks (interactively or with `--codex-hook-trust yes`) on a Codex with no earlier Pseudolife registration. The check now uses the same token as the hooks, the one in Codex's managed connection. A rerun of an affected install already passed and needs nothing new.
