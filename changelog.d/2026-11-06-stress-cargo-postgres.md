### Fixed (2026-11-06 — Stress loops really run Rust tests that need a database)
- A `mode=stress` dispatch of `cargo:` tests that need PostgreSQL used to give them no database, so they returned early and counted as run, and twenty "clean" iterations proved nothing. Exact tests covered by an entry in `CARGO_DATABASE_PROFILES` (`rust/ci/stress.py`) now get a fresh disposable PostgreSQL every iteration. They also get the embedding fixture and ONNX Runtime they need and a flag that makes a missing setup fail, and they run one at a time. The first profile covers the read-only shadow refresh tests.
- The stress plan refuses a `db_` test that no profile covers, and a profiled test mixed with other items. It warns when a whole-binary item would leave its database tests without one.
