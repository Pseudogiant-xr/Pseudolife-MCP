### Fixed (2026-11-11 — a second Codex setup on Windows no longer calls the setup lock broken) [#1469]
- When two first-time Codex setups started together on Windows, the one that lost the race to create `.pseudolife-setup.lock` could be told the file "could not be opened; repair that file and retry" instead of "Another Codex setup is in progress; retry after it finishes." Its open met a sharing violation while the winner's rename still held the new file. The loser now retries that one error for up to 500 ms and then gets the lock's real answer; any other open error, or a sharing violation that lasts past the bound, still names the file to repair.
