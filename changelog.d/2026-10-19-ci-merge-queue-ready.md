### Changed (2026-10-19 — CI runs for GitHub merge-queue groups)
- Both CI workflows now also run on `merge_group`, so a queued group reports the ruleset's required checks (`test`, `Parity / ubuntu-latest`, `Parity / windows-latest`) under the same names as a pull request. The queue itself stays off until the maintainer enables it in the master ruleset; `docs/specs/2026-10-19-merge-queue.md` lists the settings.
- A group is classified like a pull request over its own range (`merge_group.base_sha` to the group head): a Rust-only group skips the Python suite lanes, a documentation-only group skips the Rust jobs, and a mixed group or an unfetchable base runs everything. The Parity gate, the Python oracle selector, the producer-census currency check and the daemon-image input check accept the event the same way they accept a pull request.
