### Changed (2026-11-27 — client config edits check linked folders before following them)
- When the installer or `update` edits a client's config file (Claude Code, Codex, Claude Desktop), a symlinked or junctioned folder on the way to it is now checked before it is followed, by the same rule as Pseudolife's private files: a link no other account can change (your own, as with a home or config folder moved to another disk) works as before, and one in a folder other accounts can write is refused, naming the folder and the fix. A config file that is itself your link (kept with dotfiles) is still edited in place, with the folders along its own links checked the same way.
- On Linux, a link in a folder that only its group may also write is trusted when that group is your own private group (your primary group, named as you are, with no other member and no other account's primary group), as umask 002 leaves `~/.config` on user-private-group systems, and only while `nsswitch.conf` takes accounts and groups from the local files, or also from `systemd` (as Debian and Ubuntu do) while systemd's user database adds nothing to them. A group shared with anyone else, a system that also takes accounts from systemd-homed, containers, LDAP, SSSD or other directories, and every other platform keep the plain rule.
