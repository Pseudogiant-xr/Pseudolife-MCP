### Fixed (2026-11-07 — an older daemon that reconnects no longer serves a bank a newer release upgraded) [#909]
- A running daemon whose PostgreSQL session dropped re-checked the writer lease when it reconnected, but not the bank's schema stamp. If a newer release upgraded the bank in that gap, the older daemon went on serving and writing it. Both daemons (Python and Rust) now refuse such a bank on reconnect with the same message a start gives. They write nothing and close the session, so the newer daemon can hold the bank. `/health` reports the refusal until the bank is restored to a version the daemon can serve; after that, the next call reconnects.
- The schema refusal's restore hint now names the state archive beside the dump: `pseudolife-mcp restore --backup-file <dump> --state-archive <state.tgz>`, or from a checkout `ops/restore.ps1 -Apply -BackupFile <dump> -StateArchive <state.tgz>` / `ops/restore.sh --apply --backup-file <dump> --state-archive <state.tgz>`. Restoring the dump alone left the state volume at the newer release's copy. The native CLI's import guard uses the same text.
