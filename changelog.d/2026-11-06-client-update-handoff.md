### Fixed (2026-11-06 — one client update run applies the new release's client steps)
- `pseudolife-mcp update --clients-only`, and the client step of a release-mode `pseudolife-mcp update` (attended, unattended, on a client-only machine, or started by the shim's unattended client update), no longer runs the plugin, Codex hook and tunnel steps with the code of the release it is replacing. Once it has installed the new shim runtime, it hands those steps to that runtime, so behaviour new in the target release runs on the first run instead of a second `--clients-only` (0.17.0's marketplace move to HTTPS ran only on the second). The output names the hand-off ("the client steps after the shim continue in runtime …"), and the handed-off run prints its own ladder and Codex steps. It runs under its parent's update lock, keeps the caller's working directory (so relative client config paths still apply), and never hands off again.
- Its result is the run's. A `--clients-only` run, or one on a client-only machine, exits with the handed-off run's code. After a daemon deploy, a failed hand-off exits 5, as any client-step failure there does. A shim step that installed the runtime but could not move a registration also hands off, so the new code retries that move.
- A hand-off is skipped at the same version (`--reinstall`) and for a checkout deploy. It is also skipped for a target that predates it (a downgrade, a client machine following an older daemon); this run's code then finishes, as before, and says so in one line. A new runtime that cannot start fails the run (exit 5) with the cause and a `--reinstall` retry run by the working interpreter; the old code never stands in for it. A handed-off run that stops before its client steps is reported with its own reason.
- Rollout: the hand-off runs in the release being replaced, so it first helps the update *from* the release that ships it. Updating *to* that release still needs a second `pseudolife-mcp update --clients-only` for its own client-step changes. The release-procedure skill's step 6 says which case applies. The native (Rust) updater keeps the two-run shape for now (#1308).
