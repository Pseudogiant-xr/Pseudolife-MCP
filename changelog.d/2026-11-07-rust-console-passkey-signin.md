### Added (2026-11-07 — the Rust daemon signs the Console in with the maintainer passkey)
- The Rust daemon now serves the Console's passkey sign-in as the Python daemon does: the pre-auth `POST /api/console/passkey-challenge` (at the passkey origin only, a challenge bound to the browser's token, read without ever creating the challenge secret), the passkey body of `POST /api/console/session`, and "Use this passkey to sign in" (`POST /api/console/passkey-bind`, owner principals only). `/health` reports `console_signin.passkey: true` where passkeys are set up, so the Console offers the option there instead of only the sign-in code. Switching a passkey-enabled install to the Rust daemon no longer drops the passkey sign-in.
- A key enrolled in the Console on the Rust daemon records the principal it signs in as, and revoking or cancelling a key there, or binding it to another principal, signs that key's browsers out at once, in the same transaction. The native client's host `pseudolife-mcp maintainer revoke` and `reset` end those sign-ins too, as the Python CLI does.
