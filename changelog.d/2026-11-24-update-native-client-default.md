### Changed (2026-11-24 — an attended update moves a Python-client machine to the native client)
- `pseudolife-mcp update` from a Python client (0.23.0 and later) moves the machine to the native client by default, also `update --clients-only` on this release's Python client. Before, it moved only with `PSEUDOLIFE_SHIM_ENGINE=native`.
- The scheduled `update --unattended` and the shim's session-start client update never change the client; they keep the Python client, as does a run whose starting command cannot be read or parsed. The arguments are read as the updater parses them, abbreviations included. The line it prints names `pseudolife-mcp update --clients-only` to move.
- A Python client recorded by an installer run with `PSEUDOLIFE_SHIM_ENGINE=python` (`~/.pseudolife-mcp/client-engine`) is kept by later updates until `PSEUDOLIFE_SHIM_ENGINE=native` asks again. A record that exists but cannot be read keeps the Python client too, and the line names the file. The record is removed once a move with that setting has moved the launcher. A record that cannot be removed is reported.
- By default a machine whose Python client registered a tunnel to start by itself keeps that client. The update names `PSEUDOLIFE_SHIM_ENGINE=native pseudolife-mcp update --clients-only`, which prints how to remove the autostart without changing anything and moves the machine once it is gone. A platform with no native build now says so, instead of saying nothing.
- After a native run that started and failed, the update now names `PSEUDOLIFE_SHIM_ENGINE=python` as the setting that keeps the Python client.
