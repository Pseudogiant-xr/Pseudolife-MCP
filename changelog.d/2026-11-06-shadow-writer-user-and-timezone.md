### Fixed (2026-11-06 — the read-only Rust shadow starts beside a real writer and shows its local times) [#1316]
- `update --engine rust --shadow` no longer crash-loops with `cannot read /data/config.yaml: Permission denied` when the Python writer's `config.yaml` is private (mode 0600, owned by the daemon user). The companion now runs as the writer's daemon user, uid 10001, with every capability still dropped. The Rust image gives its `/models` directory to that user, so a new shadow model cache is writable by it. A shadow model cache created by an earlier version stays root-owned, with a bundle directory uid 10001 cannot read. On such a host the companion fails its startup gate and its log says a model artifact is missing, although the files are there. Remove the companion (`update --engine python --shadow --checkout <repo>`), then that project's model cache volume (`docker volume rm <project>_pseudolife_shadow_models`; for the default project, `pseudolife-mcp_pseudolife_shadow_models`), and start it again. The models download again, which can take up to 30 minutes.
- The shadow now takes the writer's `TZ`, `PSEUDOLIFE_WRITER_ID`, `PSEUDOLIFE_MCP_TOOLSET` and `PSEUDOLIFE_MCP_TIER_MAP`. Before this, it rendered local timestamps and dates (`asserted_at`, `last_confirmed`, entry `date`) in UTC and reported the writer id as `unknown`, so every comparison against a writer outside UTC differed.
