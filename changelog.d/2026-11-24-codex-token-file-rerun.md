### Fixed (2026-11-24 — rerunning a client-only install with the same token file leaves Codex's registration alone) [#1903]
- A client-only install with `--token-file <file>` stores the token in Codex's own copy (`~/.codex/pseudolife/token`) and registers that copy. Running the same command again used to re-point the Codex registration at `<file>`. Now `pseudolife-mcp connect` and the installers keep Codex's own copy while it holds the same token as the file named, so an identical rerun changes nothing. Naming a file that holds a different token still moves the registration to that file, as before. Naming a different file with the same token now also keeps Codex's copy. A registration that names your own file, not Codex's copy, still follows the file named, as before.
