### Changed (2026-10-16 — shim and daemon move to the MCP SDK 2.2 line together)
- The `mcp` dependency moves from `>=2.1,<2.2` to `>=2.2,<2.3` in `pyproject.toml` and the shim runtime's requirements, and the daemon image's lock moves `mcp` and `mcp-types` to 2.2.0 (mcp 2.2.0 requires `mcp-types==2.2.0`, which the dependabot bumps left at 2.1.0). Both sides move in one release because each release pins one SDK line for shim and daemon; the floor rises too, so an in-place `pip install -U` cannot keep a 2.1 SDK. The Rust parity oracle moves from 2.1.1 to 2.2.0 with them: the workflow's SDK installs, the validation-schema generator's version assert, and `rust/daemon/src/mcp/validation-schema.json`, regenerated. The regenerated schema accepts and rejects the same inputs: 2.2.0 inlines the `RequestId`, `ProgressToken` and `LoggingLevel` definitions that 2.1.1 referenced. The daemon keeps 2.1's session lifetime, with no idle close and no session cap: it overrides 2.2's defaults (closing a session after 30 idle minutes, and answering 503 to a new one while 10,000 are open) with `session_idle_timeout=None, max_sessions=None`, so the Rust parity row `MCP-LIVE-SESSIONS` still holds.
- `pseudolife-mcp update` moves both: the daemon first, then a new shim runtime. Sessions that keep their old shim until they restart still work: a shim on mcp 2.1.1 against a daemon on 2.2.0 passed initialize, `tools/list` (38 tools, the same catalogue byte for byte as from a 2.1.0 daemon), `memory_stats`, `memory_store` and `memory_search` through a real stdio shim with a bearer on loopback (2026-10-16). The reverse mix, a 2.2.0 shim against a 2.1.0 daemon, passed the same check; its 2026-09-28 tailnet failure still has not reproduced on loopback.
- On mcp 2.2 the SDK reads its listen stream and resumed responses through `sse_within_origin`, which the shim's 16 MiB SSE event limit no longer reached, leaving those paths at the 1 MiB default. The shim now widens that function as well, and the test drives the SDK's own function rather than a wrapper.
