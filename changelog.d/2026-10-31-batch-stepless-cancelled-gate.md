### Fixed (2026-10-31 — a pull request whose CI was cancelled as its gate started joins a batch)

- `python ops/integrate.py build` no longer leaves a pull request out as `unverified` forever when cancelling its own CI landed while the `Parity / <os>` gate job was starting: GitHub then marks the gate `failure` with no steps at all, which the script could not tell from a real failure, and no retry could read steps that never existed (#1074 at `7cb16da6`, 2026-10-31). Such a leg now counts as giving no verdict when its run attempt itself concluded `cancelled`; every other condition still applies (no other job of that attempt failed, timed out or needs action, a needed job was cancelled and none ran past its timeout). A stepless gate in an attempt that did not conclude `cancelled`, or whose run record describes a later attempt, still keeps the pull request out as `unverified`.
