### Fixed (2026-10-25 — the installer says when a firewall cuts the daemon off from the dream shim)
- In the Claude and Codex CLI shim modes on Linux, `ops/install.sh` now asks the daemon's container whether it reaches the shim, the way the endpoint modes already did. A host firewall such as ufw drops the container's traffic to the docker bridge address the shim binds, so the shim answered on the host, the install said Healthy and Done, and every dream paused. The installer now warns with the cause and the fix: the exact `sudo ufw allow` rule when ufw is enabled, the shim's unit when the shim itself is down, and the blocked port for any other firewall; the summary marks `[!] Extractor shim`.
