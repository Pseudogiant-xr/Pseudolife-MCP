### Fixed (2026-11-24 — a first native install with Codex hook consent approves board mail, and a rerun changes nothing) [#1903]
- A first native install that approves Codex's hooks (`--codex-hook-trust yes`, or a yes at the prompt) now also sets `approval_mode = "approve"` for the `memory_message` tool, as that consent says. The hook step runs before the installer registers Codex's `pseudolife-memory` server, so the approval used to fail with "Codex's user configuration has no pseudolife-memory server". The first rerun then added it, so a rerun of a set-up host changed the Codex registration.
- Now the hook step writes nothing yet and says the approval follows the registration. Right after `codex mcp add`, the runtime-defaults step applies the approval and prints what happened. If that registration fails, the next installer run with consent approves it. Both native installers (`install-native.sh`, `install-native.ps1`) do this. A value you set yourself is still kept, and without consent nothing is approved.
- `install-native.sh --transport http` now also sets Codex's runtime defaults after registering, as `install-native.ps1` already did.
- The installers now need a native client that answers installer protocol 5. A release older than this change is refused before anything changes, as for earlier protocol rises.
- A host moved from an older Python client by `pseudolife-mcp update --clients-only` still has no approval, because those installers lost it the same way, and an update never grants an approval. The next installer run with hook consent completes it. Every run after that leaves the approval alone.
