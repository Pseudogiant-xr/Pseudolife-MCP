### Fixed (2026-11-06 — the read-only Rust shadow stops running out of memory beside a busy writer) [#1322]
- A read-only Rust shadow next to a live Python writer no longer rebuilds its whole resident bank every time the writer's reads touch the database. The writer's read path changes `entries.access_count`, reinforcements, the counters, episodes and session meta. Each of those used to make the shadow's next request hydrate every store beside the copy still in use, roughly doubling its memory, so it was OOM-killed at its 6 GiB cap. It now reloads only the stores whose tables changed. It patches telemetry-only entry changes in place, and on a one-band bank it appends new entries in place.
- Measured on a disposable restored bank (about 5.4k entries, 11k facts, multi-band preset) under a 7 GiB cap. A writer replayed those read-path writes every second, plus an entry insert every 30 seconds, while 58 kinds of reads looped continuously. Peak anonymous memory went from 7152 MiB (the cap, 21 OOM kills) to 4245 MiB (against about 4.1 GiB idle), with no failed reads.
- Still rebuilt in full, and so still briefly doubled: the bank, on entry content changes, dream-state changes, and any telemetry change while a multi-band bank has a band over capacity; and the facts, world-facts or lessons store, on a change to its own table.
