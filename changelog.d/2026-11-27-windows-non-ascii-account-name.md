### Fixed (2026-11-27 — the PostgreSQL default user works for a Windows account with a non-ASCII name)
- On Windows, a database address with no user name takes the account name as the PostgreSQL user, as libpq does. For an account named with characters outside ASCII (`José`, `李雷`), the native client found no user and refused to connect, or used the wrong name. When the profile folder's name had characters outside the system code page, it also looked for the default password file (`%APPDATA%\postgresql\pgpass.conf`) in a folder that does not exist. Both now come from the Windows wide-character calls, so the account's real name and profile folder are used.
