### Fixed (2026-11-10 — Rust daemon starts on a config that sets a recall, deep-dream or lessons cap to null)
- A `config.yaml` that set `memory.recall.time_budget_seconds` to null (`null`, `~` or an empty value) started the Python daemon with no recall time budget, but stopped the Rust daemon at startup with "memory.recall.time_budget_seconds must be a number, got null". The same was true of `memory.recall.expand_budget`, `memory.recall.max_searches_per_hop`, `memory.recall.max_total_searches`, `memory.deep_dream.max_fallback_mentions` and `memory.lessons.synthesis_max_signals`, which Python reads as `value or None`, so a null turns that cap off. It was also true of `memory.graph_insight.betweenness_sample`, where a null means exact betweenness. The Rust daemon now reads a null on each of these seven keys as 0, which already means off (or exact) there. For the three recall knobs the Console shows, it still serves the value as null, as Python does. Any other non-number value, such as `abc`, still refuses startup with the same message as before.
