### Fixed (2026-11-07 — checkout Rust activation no longer fails its health gate while the models download)
- `update --engine rust --checkout <repo>` no longer fails its health gate, and rolls back, on a host that has not cached the Rust daemon's models yet. The new daemon used to download about 2.4 GB of pinned models on its first start, which took longer than the gate's roughly 45 seconds; the only workaround was a manual retry with a large `--health-retries`. Checkout activation now tags the running image for rollback, then builds the daemon and installs its pinned models while the running daemon keeps serving, then backs up, recreates the daemon and gates it, as release mode already installs its models first. The rollback tag comes first because a rebuild of the same engine moves its `:checkout` tag, after which Docker's containerd image store (the default for new Docker Desktop installs) can no longer tag the running image by its ID. A failed build or model download deploys nothing: the running daemon keeps serving, no backup is taken, and the error names the rollback tag that was kept and, after a successful build, says that `pseudolife-daemon-<engine>:checkout` now names the unvalidated build.
- The checkout Rust overlay (`ops/docker-compose.rust-daemon.yml`) keeps the models in their own `pseudolife_rust_models` volume at `/models`, the same volume as the release overlay, instead of `/data/models`, so the models stay out of every backup. A host that already ran the checkout Rust daemon downloads them once more into the new volume on its next checkout update, with no manual step; the old copy under `/data/models` is left in place and can be deleted. A printed rollback to a Rust daemon that already used `/models` includes that overlay, so the restored daemon keeps its models; a rollback to an older one that read `/data/models` leaves it there. The overlay is applied after `ops/docker-compose.override.yml`, so it replaces a `PSEUDOLIFE_DAEMON_MODELS_DIR` set there; a daemon given its own ONNX model directory with `PSEUDOLIFE_DAEMON_ONNX_DIR` is still left to manage its models itself.
- A failed engine health gate now names the check that failed: no `/health` answer, a status other than `ok`, the wrong version or schema (with the value it reported and the one expected), `counters_import_required`, a shadow that is not ready read-only, or a refused authenticated bank read. This applies to checkout and release engine changes, in both the Python and native updaters.
