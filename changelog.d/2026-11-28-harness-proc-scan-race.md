### Fixed (2026-11-28 — the batch harness no longer refuses a run when an unrelated process exits during its cleanup scan)
- `ops/rust-harness-remote.ps1` scans `/proc/*/cmdline` before it removes the run's environment. A process reaped between the listing and the read failed with "No such process", which refused the whole run (exit 3) and could redden a batch's `test` job or harness gate. A read that fails once the process's directory is gone now counts that process as gone; a failed read of a process that is still listed, and a live process naming the environment, are still refused.
