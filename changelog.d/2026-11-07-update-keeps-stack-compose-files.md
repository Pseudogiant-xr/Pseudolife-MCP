### Fixed (2026-11-07 — native update keeps a stack's own docker-compose.yml)
- The native release-mode `pseudolife-mcp update` replaced every Compose file of the running project that shared a shipped file's name (`docker-compose.yml`, `docker-compose.ghcr.yml`) with the release archive's copy, wherever it lived. A stack manager's own file, such as a Portainer stack's `docker-compose.yml`, then lost that stack's settings (ports, mounts, credentials) on recreation. Only a packaged copy (a checkout's `ops/`, a release archive, the Python updater's bundled copies) is replaced now, as the Python updater already did.
