### Fixed (2026-11-07 — Rust daemon stores a list rationale in a graph proposal)
- `memory_graph_review(action="propose")` with a proposal whose `rationale` is a list failed in the Rust daemon with an internal error after creating the proposal's entities, while the Python daemon stored the list as PostgreSQL array text. The Rust daemon now stores the same text (for example `{a,"two words",NULL}`, or `{{a},b}` for a nested list of strings), and the Console's `POST /api/graph/assign-scope` stores a list `source` the same way instead of answering 500. A list the Python daemon also cannot store, such as one mixing strings and numbers or a ragged list of numbers, still fails in both.
