### Fixed (2026-11-27 — fewer stalls behind daemon locks, and three request panics become errors)
- An access-count sync the database refuses is now retried by the next autosave. Before, the daemon recorded the save as done, so counts accrued by searches stayed unsaved until some other write, and a restart in between lost them.
- The sweep's run and retrieval-log prunes no longer hold the service's init lock, so a tool call that arrives during a large first prune is not made to wait for it. A Console config save (`POST /api/config`) now runs its file backup, replace and fsync on the blocking pool instead of an async worker. Revoking a passkey drops its sessions and the key in one step, so no request can see the key gone while one of its sessions still signs in.
- Three panics are now answers: a modern MCP request whose task failed returns the JSON-RPC internal error (`-32603`) instead of dropping the connection; a static file whose platform MIME type holds a control character is served as `application/octet-stream`; and re-judging review proposals no longer panics on a hand-edited, non-object judgments memo in `meta` (it starts a fresh memo).
