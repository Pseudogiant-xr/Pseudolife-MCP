### Added (2026-11-07 — Route one Windows parity shard to a free self-hosted worker for trusted batches)
- For a same-repository integration batch or a master push, the parity planner can now move the Windows `w1c-connection` shard to a self-hosted Windows worker, through the same planner, token and event boundary as the Linux pool. It does so only when `PARITY_BATCH_WINDOWS_POOL` is `self-hosted` and the controller's fresh `PARITY_WINDOWS_HEALTH` shows a worker that can take the job now: either running with an idle runner, or stopped, clean and startable under the host-memory guard, with no other Windows job queued. Anything else keeps hosted, and the required checks keep their names and verdicts.
