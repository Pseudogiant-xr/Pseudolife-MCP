### Performance (2026-11-27 — writes no longer hold the write lock while they embed)
- `memory_store`, `memory_fact_set` and `memory_set_add` (and the dream's claim writes, its batch hints, slot resolution, session digests and lesson synthesis) now compute their embeddings before taking the daemon's write lock, since each embedding depends only on the call's own text. Requests that need the lock, such as a search's ranking, the Console's reads and other writes, no longer wait out a write's model forward pass. A search whose query is not cached still embeds it on the same model, one pass at a time. With the opt-in `memory.cortex.auto_promote`, a store's per-slot promotion embeddings still run under the lock. Stored rows, vectors and answers are unchanged.
