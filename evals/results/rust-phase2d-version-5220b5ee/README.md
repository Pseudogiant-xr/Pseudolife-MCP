# Warmed CLI version evidence at 5220b5ee

Windows and Linux CPU captures executed `5220b5ee4cf4b7ae235ee070109b8de17fa3a1d0`, tree `11e7267bd7a884ace22f57ebf5afd6c77ee25f91`, against Python oracle `3c01bb31abd60178e15dea99adda369b4bbf92fc`. This packet keeps those source and image identities separate from the evidence branch that stores it. It retains the unresolved Linux parallel failure and does not claim stdio, full-suite or ported acceptance.

[Windows projection](windows.json) and [Linux projection](linux.json) retain the capture summaries unchanged. The [manifest](manifest.json) binds their bytes, the four timing-row files, build and helper hashes, and retained failure qualifications; [source](source-manifest.json) and [instrument](instrument-manifest.json) manifests distinguish canonical Git blobs from captured checkout hashes, including CRLF and one mixed-newline test fingerprint. Canonical source can be read at [executed 5220b5ee](https://github.com/Pseudogiant-xr/Pseudolife-MCP/tree/5220b5ee4cf4b7ae235ee070109b8de17fa3a1d0); receipt ownership does not transfer to another head.

Each OS passed 28 exact-output/state cases and 112 rejected controls, including marker-present/native-present/named-console-missing fallback and UTF-8 output with a non-ASCII home. The eight unchanged original CLI nodes passed once, non-skipped, for each Python/Rust arm; these are process arms, not Cargo feature arms. Linux's unchanged Rust version contracts passed serially 8/8 with default features and 8/8 without defaults, and 12 new focused harness tests passed. The preceding parallel run passed six tests and failed two with `ETXTBSY`; its cause remains unresolved, and serial success does not imply parallel success. Native invalid-argv coverage is one case per OS.

The new release images are Windows `2ec6ce230d7aa06f016fbc63342ec2f5f70ebd9b7d2c28a5d43493048cb02916` (13,267,968 bytes) and Linux `0b10d4618844c7cb8b7f0194fb8cf89ce5cd0292090cca732c80f2ea72a9b4a5` (16,826,112 bytes), built from 5220b5ee with Rust 1.94.0. Genuine installed Python/package versions were 3.11.9/0.17.0 on Windows and 3.11.15/0.17.0 on Linux. Interpreter dependencies are excluded from the Rust image sizes; hashes and build receipts are provenance, not reproducible-build attestations.

Each layout used two untimed byte controls, six warm starts, and three alternating repeats of ten timed starts per arm. Warm and timed starts reused each arm's unchanged file identity and restored equal input state. The timing includes owned-process setup, complete output collection and clean exit; preparation/reset/file checks are untimed. The retained `cold_start_to_exit_ms` field measures a fresh process on a warmed image, not a cold image or a daemon startup.

Historical cold-copy observations and the ~110 ms installed regression remain in the [historical packets](../rust-cli-historical-evidence.md), with no proven causal attribution; this protocol change does not explain the cold-copy cost. Initial stale-image, metadata, parallel-contract and audit-selector failures remain identified rather than counted as passes. An audit-log hash captured before final printing is retained alongside the final log hash. Linux's copied eval overlay is globally dirty while its pinned production/original-test guard is clean; the broad instrument fingerprint is not an assertion that every listed file was executed.

No daemon, database, GPU, model download or full suite ran for these CLI captures. UTF-8 is the scoped stream contract; locale/default encodings are not emulated. Captured fixture roots and owned process subtrees were removed; packaging these existing results launches no new runtime, benchmark or test. Hosted CI and any readiness decision are separate evidence streams.
